# 不喜欢与负反馈学习（已确认）

## 架构

沿用浏览器 → Host → Application → Store 保存反馈；Application 读取持久化通知 → Recommendation → Store 应用学习。推荐只给完整候选组合评分，候选仍提供合法组合，Task 只执行确定提示词；编码器、特征表示和模块依赖方向不变。

## 调用与数据流

漫游普通/沉浸菜单新增同一个不喜欢按钮，放在喜欢右侧，顺序为上一张、播放/暂停、喜欢、不喜欢、毛玻璃（沉浸）、下一张。键盘上方向键喜欢，下方向键不喜欢；重复方向键不撤回，重复点击已选按钮撤回。喜欢与不喜欢互斥，反馈后保持当前图片，自动播放沿已有计时继续；不新增强制切图或图片删除。

App 在同一 SQLite 事务保存图片三态反馈与生成时完整提示词快照的事件，再调用推荐应用服务处理。重复同状态不追加证据。喜欢→不喜欢、撤回、重新反馈均先移除旧证据，再加入新的有效证据；学习失败保留反馈，沿用现有通知恢复、重放和重置边界。图片清理后，已学到的快照证据仍保留。不喜欢沿未喜欢图片的清理规则处理。

学习以整张图的组合特征 x 为单位。有效反馈目标 y 为喜欢 +1 / 不喜欢 -1；未评价没有证据。M += xx^T、b += y*x；撤回先减去旧 M/b 贡献。更改反馈在一次模型提交中撤旧加新，维持每图一份有效证据。评分仍为 Thompson Sampling，并保留探索；相似候选通常降分，不作硬屏蔽，也不把一次不喜欢扩展为每个词永久禁用。固定词与抽取词仍沿当前特征方式处理；若候选始终包含同一固定内容，推荐不能替候选模块移除它。

## 接口

- 既有 PUT /api/artifacts/{id}/feedback 的 value 接受 1 / -1 / null，返回 artifact.feedback 同样三态。其余返回字段及 Host 路由不变。
- Recommendation.apply_feedback 的 FeedbackUpdate.liked:bool 改为 value:int|null（1/-1/null），明确 null 是撤回，不是负反馈。score 接口和 Candidate/Task 接口不变。
- 推荐存储事件、有效证据同步使用 value 三态，保留原 revision、快照和重置分界。commit_feedback 幂等与修订校验继续使用。
- 既有 GET /api/recommendation/preferences 不新增字段；evidence_count 与每词 evidence_count 表示有效喜欢和不喜欢反馈总量，界面从“有效学习点赞”改为“有效学习反馈”，权重继续显示有符号数值。重置同时清除正负学习。

## 数据与实施范围

所有数据继续在 data/pictide.sqlite3。发布前完整备份；对当前 feedback / recommendation_events / recommendation_evidence 的约束与 liked 字段做一次性结构调整，保留原点赞、原撤回、事件序号、偏好矩阵与重置记录：旧 liked=true 对应 value=1，false 对应 null。移除原只允许点赞的旧兼容转换，不引入多版本迁移框架，不清空用户偏好。算法策略版本标明支持正负反馈；编码特征版本与向量缓存保持。

本次按钮仅在漫游及其沉浸模式新增；生成/喜欢页现有点赞入口保持，后端三态接口共用。仅有有效生成快照的反馈进入学习，手动文本仍不伪造词条归因。

## 验证

少数冒烟验证同图重复不重复学习、喜欢↔不喜欢↔撤回贡献可逆、负反馈使对应组合中心评分下降、重启/重放/重置语义、既有点赞数据在当前数据库结构调整后保留。前端类型检查/构建与隔离中性图片交互。发布前通知重启并保留正在执行任务；不为验证派发真实 GPU 任务。

## 本次验证结果

已通过：正负反馈 HTTP 保存与学习、重复/撤回/反转的贡献可逆、学习失败后的重启重放、重置阻止旧证据恢复，以及原点赞存储路径。使用中性样例在浏览器核实普通与沉浸菜单、↓ 替换喜欢、重复 ↓ 保持不喜欢、按钮撤回和刷新保留；前端类型检查与构建通过。生产数据库副本的 20 张表转换前后内容校验一致，84 条原反馈、偏好矩阵、事件修订和重置分界均保留，外键检查通过。未提交真实 GPU 测试任务；长期推荐效果待用户反馈验证。
