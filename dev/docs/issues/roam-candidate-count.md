# 漫游候选组合数量（已确认）

## 架构

模块边界保持不变。设置保存在应用 SQLite，由应用编排读取；候选模块生成完整组合，推荐模块只评分，编排选中组合后交给任务模块。

## 调用与数据流

1. 设置 → 漫游增加「候选组合数量」数字输入，默认 4，范围 1–20（整数），与现有设置一起保存。
2. 浏览器 → Host → 应用编排 → 漫游设置存储，沿用既有 HTTP 与设置事件。
3. 新建漫游任务时，编排把已保存数量传给候选 provider.generate 的现有 constraints.count；把返回的全部组合交给推荐，选择最高分组合生图。
4. 停泊已有参考组合时仍直接复用；推荐不可用时仍采用第一个组合。
5. 修改数量只影响之后新准备的组合池，保留当前图、已有预取和任务；只修改此字段不清空缓冲、不切换漫游 epoch 或重置暂停状态。手动生成不受影响。

## 接口

- GET /api/settings/roam 和既有包含漫游设置的响应增加 candidate_count，默认 4。
- PUT /api/settings/roam 接受 candidate_count；支持单独保存此字段，完整表单未传时保留原值。
- 基础设置为 1–20；候选 provider.generate 的 constraints.count 支持 1–100，以容纳强力倍增；力度与评分接口见 [推荐力度](roam-recommendation-strength.md)。
- 漫游设置内部 get/save/save_options 支持该字段，SQLite 的 roam_candidate_settings 表持久保存。初始化不删除现有图片、任务、偏好和设置；修改前备份数据库。

## 验证

少量冒烟检查默认值、范围校验、保存后读取，以及所设数量传到候选并完整交给推荐；前端类型检查、构建和设置页实际交互。数量越大，候选生成与评分等待通常越长；图片数量仍为每个任务实际输出的数量。

已验证：2 个 HTTP/编排冒烟通过，覆盖默认值、范围、重启持久化、完整表单/单字段保留 epoch 与暂停状态、7 个候选全部交给评分且原待执行任务保留。类型检查和构建通过；隔离界面将数量从 4 改为 7，保存并刷新后保留，无控制台错误。未提交真实 GPU 测试任务。
