# 跟随系统主题（已确认）

## 架构与调用

沿用 Web → Host → Application → Store → SQLite，复用现有通用设置接口和 general_settings SSE 事件，不新增模块。浏览器负责解析系统外观，服务端只保存主题选择。

## 接口与数据

GET/PUT /api/settings/general 的 theme 从 light | dark 扩展为 system | light | dark，对应界面“跟随系统 / 白色 / 黑色”。默认 system，已有明确保存的 light/dark 保留。其他输入仍返回 400，保存失败保留原值。

复用 general_settings 表，不调整表结构；选择 system 删除 id=1 的显式主题记录，读取空记录返回 system。数据库仍是配置唯一来源，不保存 localStorage 副本。发布前备份数据库；不触碰图片、任务、反馈和偏好。

## 浏览器数据流与界面

通用设置使用共享 shadcn 单选分段控件展示三个选项。进入页面先读取主题选择；system 使用 matchMedia('(prefers-color-scheme: dark)') 解析实际黑白外观并订阅 change。只有 system 随系统变化，显式 light/dark 保持固定；系统变化只更新显示，不触发设置写入。所有页面和浮层共享根节点主题。

切换选择立即应用并保存，失败回退之前的选择（包括 system），已有 SSE 同步其他已打开页面的选择；每个浏览器按自己的系统外观解析 system。主题选择与实际显示颜色分开保存到前端状态，确保系统黑色时仍选中“跟随系统”。

## 验证与发布

少数冒烟覆盖默认值、三项保存/重启读取、非法值不改数据、系统变化仅影响 system 和保存失败回退。前端类型检查、构建及隔离浏览器检查选择/同步/布局。后端重启前核对活动任务并告知，备份并保留用户数据。

## 实施验证

2 个 HTTP 冒烟、1 个系统外观事件冒烟、前端类型检查与构建通过。隔离浏览器确认默认选中跟随系统、黑白切换、SSE 跨页面同步、刷新保留，以及模拟保存失败回退 system；未提交生图任务。
