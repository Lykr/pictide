# 漫游推荐力度（已确认）

## 架构

维持浏览器 → Host → 应用编排 → 候选 / 推荐 / 任务 / 存储的边界。候选生成完整组合，推荐只为输入组合评分；力度由编排转成候选数量与评分策略。标准和强力使用同一份用户偏好与反馈学习，不新增学习器或生成循环。

## 调用与数据流

1. 漫游折叠菜单增加「推荐力度：标准 / 强力」，默认标准，立即保存。设置 → 漫游提供同一选项与「强力候选倍数」（整数 1–5，默认 2），沿用现有保存方式和实时同步。
2. 编排读取基础 candidate_count（1–20）。标准生成 N 个完整组合；强力生成 N × strong_candidate_multiplier 个，最多 100 个。不改变每组标签数量，不静默截断倍增数量。
3. 编排向候选传现有 constraints.count。向推荐提交完整池：标准 strategy=thompson，强力 strategy=mean。
4. 标准沿用 Thompson Sampling；强力求解 Mθ=b 得到后验均值，使用 xᵀθ 评分，不生成随机参数、不加探索项。编排选最高分；同分稳定选择输入顺序首项，不随机打破平局。同一池和同一学习状态的强力评分保持一致。
5. 候选生成仍保持既有随机 / 顺流 / 停泊语义。停泊已有参考组合时直接复用，不扩展池或评分；推荐不可用时沿用已有明确降级提示与首候选，不暗中改为探索评分。偏好数据不足时不宣称已经知道用户最喜欢什么。
6. 切换力度或倍数只影响之后准备的新候选池。保留当前图片、已有预取、已排队任务、播放状态和 epoch/暂停状态；手动生成保持现状。
7. 生图快照记录 scoring_strategy；反馈仍学习原完整组合。评分策略不会进入词项特征，不触发偏好清空或特征重建。

## 模块接口

- 既有 GET/PUT /api/settings/roam 与 bootstrap 漫游设置增加 recommendation_strength: standard|strong、strong_candidate_multiplier: 1–5。支持单字段 PATCH 风格 PUT；完整表单缺字段保留已保存值。存储内部 get/save/save_options 接收对应字段并保存应用 SQLite，变更前备份。
- 候选 provider.generate(context,constraints) 的 count 范围从 1–20 扩为 1–100；基础候选数量设置仍为 1–20。
- ScoreRequest 增加 strategy: thompson|mean，默认 thompson；输入非法值拒绝。ScoreResult 保持每个组合返回一个分数，返回结构不变。
- 应用编排映射力度到上述两个接口；任务提交接口、图片反馈接口及偏好学习接口不变。

## 最少验证与发布

少量冒烟覆盖设置持久化与范围、倍增数量完整传给推荐、强力在不同 sampling_seed 下分数相同、标准仍可采样，以及切换保留旧任务/epoch/暂停。类型检查、构建、隔离浏览器验证菜单与设置同步。发布前备份与核对任务，重启提前告知；不派发真实 GPU 测试任务。
