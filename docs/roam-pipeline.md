# 漫游预取流水线（已确认）

## 架构

复用浏览器 → Host → Application → Candidate / Recommendation / Task / Store。模块边界不变；Task 继续单任务出图，不同时提交多个 GPU 任务。不新增定时器、调度进程或配置项。

## 调用与数据流

现状：Application 和 Store 都用全局 pending 非零阻止预取，必须等出图完成才能生成下一份提示词。

调整：每次 ensure 仍最多创建一个漫游任务，创建后唤醒 Task 并发布既有 jobs 事件。后续页面/SSE 事件再次 ensure，可在上一张出图期间执行下一组候选生成与推荐评分，再持久化已准备的任务。最多保留两个未完成漫游任务（排队、提交中、运行中），即一个出图、一个提前准备；手动任务不占此漫游额度，仍在出图队列中优先。

ready + roam_pending 达到 target 时停止补充；roam_pending 达到 2 或全局 pending 达到原漫游创建容量 10 时等待后续事件，不作为失败暂停。暂停/取消和设置 epoch 逻辑保持。统计所有版本的未完成漫游任务，避免修改设置后重复准备。已有自定义工作流每个任务可能多张图，因此 pending 按每任务至少一张保守估计，与原产物统计一致。

## 任务交接

Task 工作线程在当前任务完成、失败或进入待核对状态后，立即重新读取持久队列并处理下一项，不再固定等待 2 秒。任务选择继续沿用已接收任务优先、手动排队任务先于漫游的顺序；图片下载、保存与结果入库完成后才推进下一项。运行中优先等待生成后端结束事件，健康连接每 30 秒兜底核对；不支持事件、断线或查询失败时按 2 秒查询。空队列等待入队通知，有不确定提交时约每 30 秒复核。具体适配器接口、生命周期与恢复策略见 [生图任务事件通知](task-events.md)，不增加并行 GPU 任务或配置项。

## 接口

POST /api/roam/ensure 的输入不变；返回新增只读整数 roam_pending（所有未完成漫游任务数），pending 继续表示全局未完成任务数。Store.ensure_roam 的参数不变，同样新增 roam_pending 返回值；App 与 Store 共同检查库存和容量，Store 事务保证并发请求不超额创建。其余模块接口不变。

## 验证

少数隔离冒烟：第一张模拟出图未完成时第二张提示词已准备并入队；重复/多页面 ensure 不超过两个；达到 ready+roam_pending 目标不补；手动任务优先且不阻塞提示词准备；全局容量满等待，暂停后不新增。使用临时 SQLite 和模拟后端，不发真实 GPU 任务。发布前备份并核对任务，告知重启。

已通过 3 个隔离冒烟：模拟出图等待期间下一份候选与评分完成、库存目标和队列上限/手动优先/暂停、SQLite 多线程同时提交不超限。未发真实 GPU 任务；前端资源与 GPU 执行机制未改。

任务交接优化补充验证：3 个隔离冒烟覆盖完成后立即交接与手动优先、运行中等待且不重复提交、空队列等待及新任务唤醒；另复用候选提前准备和不确定提交不重试两个用例。模拟后端配合真实 SQLite 的三次对比中，完成入库至下一次提交平均从 2029ms 降至 16ms。这是调度交接时间，不是 GPU 出图耗时；后续完成检测已改为 [事件通知与 HTTP 核对](task-events.md)。
