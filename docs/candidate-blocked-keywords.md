# 共现扩展屏蔽关键词（已确认）

## 架构与数据流

保持 Web → Host → Application → Candidate，推荐只对完整组合评分、任务执行选定组合；不新增模块或接口路径。屏蔽规则属于候选预设，不写进推荐偏好或词库。

用户在提示词 → 生成设置 → 共现扩展配置屏蔽关键词，保存到现有候选预设 SQLite JSON 文档。Candidate 在每次加权随机抽取前过滤包含任一关键词的候选标签，再沿用 PMI、数量和搜索预算生成完整组合。

## 接口与保存

预设 document 增加 blocked_keywords: list[str]，默认 []，沿用现有预设读写和 /api/candidate/generate 的 document。去掉首尾空白、空项及重复项，不添加新表或数据库列；非法类型按原校验入口报错。后端只处理规范化后的列表，词库不修改，Store 与推荐/任务接口不变。

界面复用共享 Textarea，每行一个关键词；帮助提示说明匹配规则和作用范围。示例 hair 能匹配 long_hair，black hair 与 black_hair 等价，忽略大小写。采用包含匹配（多个关键词任一命中即屏蔽），不使用正则、语义匹配或自动翻译。

## 作用范围

- 仅限制共现扩展抽取的正向标签；用户明确输入的固定正负词保持原文，不替代负向提示词。
- 应用于预览、共现生成页、随心漫游、沿途变化及原连续序列；没有固定锚点的首次抽取同样过滤。
- 沿途参考中的可变词若命中当前屏蔽关键词，不能继续保留为有效起点，按当前规则重新起步。原序列缓存键已包含预设内容，更新关键词后不复用旧序列状态。
- 驻足保持整组已固定提示词，不进行共现扩展，因此不重新过滤；没有参考而首次抽取时照常应用关键词。
- 可用词不足时沿用部分结果，不补入被屏蔽标签，不新增报错条件。固定词可使最终文本包含关键词，帮助提示明确这一点。
- 修改规则只影响后续新抽取组合，不追溯已有图片或已派发任务；不新增自动清理或取消机制。切换偏好范围/漫游方式仍按原失效规则执行。
