# 偏好范围与漫游方式（已确认）

## 界面与行为

漫游选项和设置 → 漫游同步提供两组共享 shadcn 单选控件：

- 偏好范围：全部 / 喜欢。沿用 liked_tags_only，默认全部，已有选择保留。喜欢只限制随机抽取词，固定正负词与 PMI 约束保持。
- 漫游方式：随心 / 沿途 / 驻足，默认随心。随心每次重新抽取；沿途以已有组合为起点按预设 change_budget 做增删；驻足保持整组正负提示词，图像种子继续随机。驻足时偏好范围置灰并保留选择，不过滤已固定的描述。

切入沿途或驻足时，以当前观看图片的实际提示词和快照为起点；无可用图片时先按当前预设和偏好范围生成一次。沿途的变化预算复用所选候选预设，设置界面给出来源帮助，不增加第二份预算。未知自由文本仍按原固定词机制处理，不通过语义推测词库身份。

改变范围、方式或生成预设时沿用新 epoch，下一次准备新任务使用新设置。范围或方式实际切换时，保留当前图片及较旧历史，清空其后的漫游预取窗口；缓存图片从漫游隐藏，喜欢页与文件保留。尚未执行的旧漫游任务取消，已执行的旧任务允许完成但结果不再进入漫游。生成页任务不受影响。切换生图后端/候选预设同样执行这项失效处理，防止旧配置结果混入；只修改播放间隔、预取数量或历史上限不触发。播放状态、间隔和毛玻璃保持当前机制。

## 架构与数据流

沿用 Web → Host → Application，Application 分别调用 Store、Candidate、Recommendation、Task，三个业务模块不直接交互。生成页和提示词预览保持原行为。

1. Application 根据库存决定是否需要新任务，读取漫游设置。
2. Store 查找同 epoch 最新已入队任务的实际候选快照；无此记录则取请求 anchor_id 指向的当前漫游图片。任务已经取消、失败或被切换标记失效时不作为后续起点。首个起点不存在则返回空。
3. 随心沿用完整候选池生成和推荐评分。沿途向候选模块传递同一个上一组合，各候选分别从这个组合变化，推荐只给完整组合评分；选中的结果入队后成为下一次的起点，避免把未选中的候选当成下一帧。
4. 驻足把参考组合完整保留成唯一候选，不再重新抽词；没有参考时先走一次随心及推荐选取。已选快照随既有任务事务保存，重启后从数据库恢复，避免依赖前端会话或内存游标。
5. 喜欢范围空池沿用等待行为。沿途若起点的可变词已不满足当前词库/允许范围，则按当前规则重新起步；同一有效范围内仍受变化预算约束。PMI/搜索不足沿用部分结果。

## 接口

| 接口 | 调整 |
| --- | --- |
| GET/PUT /api/settings/roam、bootstrap.roam_settings | 新增 prompt_mode: random / along / stay，默认 random；允许单独局部保存，保留其他字段。liked_tags_only 名称不变，只修改界面名称。 |
| Store.RoamSettings.get/save/save_options | 返回或接收 prompt_mode；方式实际变化更新 epoch，间隔单独保存不更新。范围/方式/后端/预设变化时，设置保存与预取失效处理在同一 SQLite 事务提交。 |
| Store.roam_prompt_reference(epoch, anchor_id) -> dict 或 None | 返回上述参考任务/图片的实际正负文本及已有标签快照；只读查询，不调用候选或推荐。 |
| CandidateProvider.generate(context, constraints) | constraints 新增 prompt_mode 和 previous_candidate（参考完整组合快照或 None）；沿途的池内每项从同一起点生成，驻足有参考时仅返回保持原文的一个候选。 |
| Candidate 内部生成 | 复用现有 _advance 和 change_budget；传入上一组合而非用递增 sequence_step 跨过未被选中的组合。原 sequence 模式接口不改。 |

POST /api/roam/ensure 的输入/返回字段不扩展；继续传 anchor_id，已有快照和 roam_jobs.epoch 足以保存顺序，不新建漫游状态表。设置 PUT 的 HTTP 字段保持上述设计，不额外加入清空接口；当前图片从已有 roam_view 读取，尚未有观看位置时清空全部预取。

## 数据、验证与发布

设置在 SQLite roam_settings 增加 prompt_mode TEXT NOT NULL DEFAULT 'random'，允许 random/along/stay。备份后做一次离线加列，新库直接包含；不引入兼容或迁移框架。用户图片、喜欢、任务和推荐学习记录保留；取消仅改变旧待执行漫游任务状态。新增 roam_jobs.discarded_at TEXT 可空字段，标记切换前尚未完成的任务，确保迟到结果失效可跨重启保留。

少数冒烟验证三种模式、预算从真正选中的组合衔接、双任务预取/重启恢复、驻足原文不变但图像种子随机、喜欢范围、局部设置保存与界面同步。前端类型检查、构建、隔离模拟后端页面验证；不提交真实 GPU 任务。发布重启前核对活动任务并告知。

## 切换预取失效处理（用户补充，已确认）

- 界面提交范围/方式切换期间暂停自动前进和旧图片窗口合并，保存成功后以新的 artifact_revision 重新读取窗口与当前图片，再恢复原播放意图；保存失败恢复原选择，不清空当前图片。旧请求返回不能把旧窗口合回页面。
- Store 在保存设置的同一事务内，以 roam_view 当前图片的 (created_at,id) 为边界，给较新漫游产物设置现有 roam_hidden_at；保留当前图片与较旧历史。隐藏只影响漫游展示，喜欢图片仍在喜欢页，图片文件和反馈保留。
- 同一事务将所有尚未执行的旧漫游 queued 任务改为 cancelled，并给所有未完成的旧漫游任务设置 discarded_at；不向 ComfyUI 发全局 interrupt，不取消生成页任务。Task 的领取与取消沿用数据库状态检查，先被领取的任务归入执行中。
- Store.complete 写入漫游产物时检查任务 discarded_at，失效任务的新产物直接带 roam_hidden_at，不出现先展示再隐藏的窗口；状态及结果记录照常保留。失效任务不计入新预取库存，也不作为沿途/驻足参考。
- 跨模块接口增量：Store.RoamSettings.save/save_options 仍作为保存入口，内部复用同一事务的预取失效操作；Store.complete 的输入输出不变，增加失效任务结果默认隐藏语义。Task 不新增调度接口。
- 验证增加：切换后旧缓存不可向右浏览、排队取消、执行中迟到结果不进入漫游、喜欢保留、重启仍失效、保存失败不改变窗口、仅改间隔不清空。
