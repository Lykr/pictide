# 漫游快速模式（已确认）

## 架构

沿用 Browser → Host → Application → Candidate / Recommendation / Task / Store。候选和推荐继续只生成、评分完整提示词组合，不接管采样步数。Application 确定漫游任务实际步数，通过 Store 固化该任务的工作流快照，Task 与 ComfyUI adapter 继续执行已有任务快照；不新增调度循环。

## 调用与数据流

### 后端步数

后端配置增加「采样步数输入」绑定和「K 采样步数」数字输入。绑定方式沿用正负提示词、图像种子的节点输入选择；默认工作流直接指向 KSampler.steps，自定义工作流只有一个合适输入时自动选择，多个时由用户选择。

正常步数仅存于所选 workflow 节点的 inputs.steps，数字输入与节点参数 / JSON 共用草稿，避免重复配置。绑定必须指向整数 steps 输入，不能覆盖连线；未绑定的工作流保持原参数，但开启快速模式时提示先配置步数，不默默只缩短播放时间。

### 播放交互

- 单击仍播放 / 暂停；双击切换快速模式并开始 / 继续播放，再次双击恢复普通模式。
- 为避免双击被执行成两次播放 / 暂停，鼠标单击短暂等待双击识别；键盘 Enter / Space 激活不延迟。
- 快速模式按钮保持环形进度和中央暂停符号，增加轻量选中背景与明确悬浮提示 / 可访问名称。普通、沉浸和菜单入口共用状态。
- 快速模式的实际展示时长 = 已保存间隔 ×展示时间系数（默认 0.5，例如 5 秒 → 2.5 秒），不改写原间隔；切换后重新计时，上方向键重置逻辑继续生效。
- 快速模式作为漫游设置保存，默认关闭，暂停不关闭此模式；刷新仍默认暂停播放。

### 可配置系数

「设置 → 漫游」增加快速模式区域，两列数字输入「采样步数系数 / 展示时间系数」，均默认 0.5，范围 0.01–1，可分别调整。数值表示相对正常值的倍数，帮助提示解释计算方式；正常模式不使用这两个系数。

切换快速模式或修改两个系数均不清理预取、不更新预取窗口。展示时间按当前模式与新系数重新计时；采样步数只影响随后新创建的漫游任务，已排队或执行中的任务保持提交时参数。普通模式修改系数只保存数值。

### 任务与预取

- Application 读取所选后端及步数绑定，从正常工作流草稿值计算实际步数。快速模式为正常步数 ×采样步数系数（默认 0.5），四舍五入到整数，至少 1 步（28→14，29→15）；普通模式使用原值。
- 普通模式、手动生成与已保存后端配置不被快速模式修改。需要快速模式时复制该任务工作流，仅替换已绑定 steps 输入，存入现有 backend_revisions 并使任务关联该快照；不更新 backends 指向的用户配置。
- 切换快速模式保留当前图、后续预取图片及所有既有任务，不取消任务或隐藏迟到结果。手动任务不受影响。
- 新创建的漫游任务使用当前快速模式和系数；既有预取图可能沿用切换前步数。图片实际生成速度不保证精确翻倍，解码等固定开销保持。

## 接口

1. 现有后端配置接口的 bindings 增加可选 steps：

```json
{"bindings":{"steps":{"node_id":"3","input":"steps"}}}
```

步数值仍从 workflow["3"].inputs.steps 读取，不新增第二个正常步数字段。ComfyUI adapter 对 steps 绑定保留配置工作流内的实际整数值，原正负词和种子注入方式不变。

2. 现有 GET/PUT /api/settings/roam 新增以下字段，持久保存在所选 data 的业务 SQLite，通过现有 roam_settings 事件同步；仅提交这些字段时保留其他漫游配置。

```json
{
  "quick_mode": false,
  "quick_steps_factor": 0.5,
  "quick_playback_factor": 0.5
}
```

两个系数均为有限数值，0.01 ≤ 值 ≤ 1。仅更改 quick_mode、quick_steps_factor 或 quick_playback_factor 都不更新 epoch，不使预取失效；实际播放时长随当前模式即时计算。原偏好范围、漫游方式等设置的既有失效行为保持。

3. Store 的 ensure_roam 增加可选 backend_snapshot 参数，Application 传入最终执行的后端快照；Store 创建任务专属 revision 并关联任务，不改变用户后端配置。Task 接口与 submit(plan,request_id) 保持不变，仍从 job_backend 读取已固化配置。

## 验证与发布

备份业务 SQLite 后实施。少数冒烟检查正常 / 快速步数、奇数取整、任务快照不污染配置、切换模式保留预取与已排队任务、双击不触发两次单击、两种系数的独立保存与生效、有效展示时长与环形进度一致。类型检查、构建和隔离浏览器验证，模拟后端，不提交真实 GPU 任务。后端发布前检查任务并提前告知重启。
