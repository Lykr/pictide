# 页面设计规范覆盖审查

审查日期：2026-11-06。页面源码基线：`1f4ef22`。本次修订设计文档，未修改前端行为。

## 结论

已有规范对视觉规格、共享组件、图片工具栏、响应式和快捷键覆盖较细；缺少把功能细节串起来的设计判断依据，且部分描述已落后于实现。修订后，五个主页面、六类设置及跨页引导都有明确归属；现有实现与新规则的差异单独列出，不当作已经完成的界面整改。

## 补齐的原则

| 原则 | 为什么需要 | 落点 |
| --- | --- | --- |
| 页面各司其职，图片与下一步优先 | 避免把连接、调参、生成、收藏都塞进同一页面，或让次要工具抢占主任务 | 设计系统入口、布局中的页面职责表 |
| 相同语义复用相同模式 | 一致性体现在动作、名称、状态和组件，而不是所有场景机械地采用相同尺寸 | 设计系统入口、控件语义表、视觉语义 |
| 用户上下文连续 | 异步刷新、保存和预加载不应换掉当前图片、覆盖草稿或重置动画 | 设计系统入口、表单保存约定、画轴与锚点规则 |
| 操作范围与生效时机清楚 | 草稿、已保存配置、本次运行、下次启动，以及任务已接受和已完成，必须能区分 | 表单规范、通用设置、各配置页 |
| 反馈与动作相称 | 点赞状态、等待进度、保存结果和历史错误各有位置，避免所有操作都弹通知 | 反馈决策表、原地反馈、通知与恢复规范 |

入口：[英文设计系统](../../../dev/design-system.md)。具体规则分别归入视觉、组件、布局与验收文档，不扩充 AGENTS.md。

## 页面覆盖核对

| 页面 / 状态 | 原有覆盖与缺口 | 修订后的归属 |
| --- | --- | --- |
| 全局导航与页面层级 | 尺寸和断点已覆盖，缺少页面职责与信息优先级 | 布局：Page roles、Application shell |
| 漫游单张 / 画轴 | 播放操作已覆盖，需明确当前图身份、锚点保存和异步运动连续性 | 布局：Roam；视觉：Image surfaces and visual meaning |
| 图片大图、毛玻璃、沉浸 | 交互已覆盖，需明确画框裁切、模糊与状态装饰分层 | 视觉；组件：Image controls；布局：Privacy、Immersive views |
| 生成 | 字段编排已覆盖，补齐任务接受与完成、草稿与结果的职责区分 | 页面职责表；组件：Forms and editing；布局：Generate and Liked |
| 喜欢、导出、恢复 | 功能已覆盖，但“大图无原图下载”与喜欢页下载规则矛盾，撤回通知相关措辞不统一 | 布局：Generate and Liked；组件：Floating notifications、Action scope and recovery |
| 提示词词库 / 编排 / 预览 | 具体交互已覆盖，需明确只读数据、可编辑配置与诊断细节的层级 | 页面职责表；布局：Prompts；表单约定 |
| 通用设置 | 外观行布局已覆盖，局域网、ComfyUI 启停和更新的不同生效范围缺少统一说明 | 布局：Settings → General |
| 漫游设置 | 旧文档把历史上限初始值写成 0，且混淆完整表单与紧凑选项的保存方式 | 布局：Settings → Roam；默认值链接回 API 的唯一来源 |
| 生图 API | 工作流控件已覆盖，需说明测试与保存、当前草稿与旧测试结果的关系 | 组件：Forms and editing；布局：Settings → Image API |
| LLM API | 连接界面已覆盖，补齐登录、模型读取、错误状态与配置保存的区分 | 布局：Settings → LLM API |
| 画幅池 | 已实现页面，但设置目录和专门布局规则漏项 | 布局：Settings → Canvas pools |
| 历史 | 任务、分页和清理区域已覆盖，补入页面职责与验收映射 | 布局：Settings → History；验收覆盖表 |
| 首次使用与引导 | 独立实现和测试已有，设计主规范缺少入口 | 布局：First use and guided help；验收覆盖表 |
| 保存、通知与确认 | “所有临时结果都通知”“保存仅限有效修改”过于笼统，与已实现交互冲突 | 控件语义、反馈决策表、保存约定、动作范围 |

## 已发现的实现差异

以下是后续界面整改项，本次没有修改对应代码：

- **偏好颜色缺少统一归属。** `web/src/components/roam-scroll.css` 为喜欢边框和爱心写入局部色值；`web/src/styles/feed.css` 的收藏缩略图喜欢按钮使用 `--destructive`。视觉规范已明确个人偏好、批量选择和错误是不同语义，反馈装饰应采用共享主题规则。后续需统一具体配色实现。
- **连接测试把等待提示也放进通知。** `web/src/controllers/backend-settings.js` 在测试开始时调用 `settingsNotice('正在测试连接…')`。组件规范明确进度留在操作处，测试完成或失败再给独立结果通知；后续应按此收敛重复反馈。

## 核对证据

- 静态核对：`feed.tsx`、`editor.tsx`、`features/`、共享组件与样式，以及现有浏览器检查。
- 隔离页面：1365×900 英文浅色、390×844 中文深色；每组采集漫游、锚点、画轴、生成、喜欢、提示词的词库/编排/预览，以及六类设置和新手引导，共 30 张截图。
- 两组页面采集完成，记录中均未出现整页水平溢出。截图与结构记录位于忽略目录 `dev/verification/design-audit/artifacts/`。
- 此次实际核对以代表性常态页面和源码为主。失败、空态及恢复的规则另与组件实现和既有检查核对；未把已有测试入口等同于本次逐一重跑的结果。

后续新增或修改页面时，在对应设计文档写清职责、主动作、生效范围、反馈位置和关键状态，再按验收表选择检查，避免规则只散落在代码或历史对话中。
