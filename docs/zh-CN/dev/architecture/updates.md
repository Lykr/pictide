# 手动应用更新

[English](../../../dev/architecture/updates.md)

[架构](../architecture.md) · [发行流程](../development.md#构建便携包)

更新只由用户显式操作触发。启动、进入设置、读取状态、定时器和已有下载缓存都不会触发 GitHub 检查或安装；已开始的下载和安装属于用户发起的操作。

## 职责

`backend/updates/` 负责发行元数据、兼容检查、下载、包校验和独立文件替换，接口位于内部 `contracts.py`，不导入候选、推荐或生图服务。`backend/update_cli.py` 在普通启动和模型准备前编排命令行操作。Host 组装更新服务，承载 HTTP/SSE 和关闭流程；Application 在安装前检查任务、并发写入和漫游状态。

通用设置通过 `GET /api/updates` 读取本地状态，只有显式 `POST /api/updates/check`、`/download`、`/install` 执行对应操作。既有 SSE 发布 `updates` 事件；下载进度不会刷新漫游或触发预取。安装只允许本机客户端，局域网客户端可以检查和查看状态。

`--check-updates` 检查并输出 JSON，不启动服务、托盘、准备引导或 MiniLM 下载。`--update` 显式检查、下载并将安装交给独立进程；已有实例时复用其 API 和生命周期，否则先检查所选数据目录中的任务记录。交接后命令退出，让 Windows 释放可执行文件；结果保存在 `data/tmp/updates/result.json`。

## 兼容与发行

`scripts/update-policy.json` 声明目标版本接受的来源版本范围。目标版本负责正常启动时需要的数据初始化或迁移，更新器只检查声明范围。发布时根据行为和持久数据的变化维护范围，版本号本身不能证明兼容性。目标还须为更新的稳定版本，匹配更新协议、平台和架构，并通过原生安装冒烟。源码检出、只读目录和数据与替换范围重叠的安装使用手动更新。

原生包在 `resources/installation.json` 中记录 schema、版本、平台和架构。发布器根据兼容策略、压缩包、构建报告和成功的原生冒烟报告生成 `update.json`。每个资源包含文件名、压缩与展开体积、SHA-256 和原生验证状态，并与 GitHub 资源元数据核对。缺失或未验证时提供手动更新。

`scripts/smoke_portable.py` 同时运行 `scripts/smoke_updates.py`。发行 CI 使用 `--previous-release` 下载并启动上一稳定版的同平台包，用旧版保存设置，验证替换失败后的恢复，再升级到新版。检查实际服务版本、HTTP 就绪、既有设置和数据库记录、备份、个人文件及 MiniLM 权重。`--previous-archive PATH` 可使用本地旧包。没有旧版时仍验证同版本替换，但不会启用 `install_verified`。版本标签推送会自动构建发行；工作流修正后，可通过[手动重跑发布](../development.md#github-actions-发版)重新构建同一固定标签。

## 安装与恢复

手动下载使用 `data/cache/updates/<version>/`，校验体积、摘要和压缩包路径、符号链接后解压。macOS 使用系统解压工具并验证包内 ad-hoc 签名，不更改系统安全设置或隔离属性。下次启动不会自动安装缓存。

更新计划和辅助进程日志放在 `data/tmp/updates/`。辅助进程直接从已校验的缓存包运行，不额外复制运行环境；文件租约避免 GUI 与 CLI 同时操作。替换前等待旧服务及 macOS 启动器退出，拒绝其他占用相同安装的进程。冻结程序重启时重置 PyInstaller 环境，确保载入正确运行库。

`data/backups/updates/` 保存一致的 SQLite 快照和被替换的程序文件。Windows 替换可执行文件及 `_internal/`，macOS 替换 `.app`，Linux 替换启动器、打包运行环境和发行文档。数据目录、目录指针、图片、模型、词库和无关安装文件不属于替换范围。

替换完成后，辅助进程通过既有 `--help` 入口检查运行库能否载入，不准备数据、下载依赖或启动服务，随后按原模式启动应用一次。替换、运行库检查或进程启动失败时恢复程序文件并尝试重启旧版。数据库快照保留供手动恢复，更新器不恢复或删除运行数据库。

运行库检查不保证后续业务初始化或运行成功；正常 HTTP 就绪由原生发行冒烟验证，不增加更新专用模式或接口。详细输出、结果和备份保留供排查恢复。

安装后页面最多等待两分钟重连，单次状态请求超时为五秒。超时后停止轮询，以悬浮通知提示查看应用日志，不再次触发检查、下载或安装；后续本地 SSE 成功重连仍可刷新页面。

macOS 原生启动器提供原始参数，正常从 Finder 启动时也明确传入空列表。Host 保留此列表，不继承服务内部的 `--cli --no-browser`，使桌面更新重启菜单栏启动器。核心回归覆盖空参数、显式启动器参数和普通 CLI 启动。原生跨版本冒烟目前验证 CLI 重启与数据保留，不验证可见的 macOS 菜单栏。

受影响的旧版本可能已经把 worker 参数保存为重启参数，无法据此可靠地区分桌面启动和有意的 CLI 启动。发生这种升级后，在活动监视器退出 `PictideService`，再从 Finder 打开 `Pictide.app`；修正后的 Host 会为后续更新记录原定模式。

## 验证

运行 `python -m unittest tests.backend.updates.test_updates -v`、架构检查和更新浏览器流程。它们使用临时数据及模拟发行、下载响应；原生包冒烟单独运行打包程序，不提交生图任务。
