# 安装与接入

[文档导航](../README.md) · 下一步：[提示词](prompts.md) / [漫游](roam.md)

先准备 ComfyUI 和可用的文生图模型，再启动 Pictide。词库共现扩展需要已导入的候选库，推荐学习还需要本地 MiniLM；手动输入文本生图可独立使用。

## 启动

| 系统 | 启动方式 |
| --- | --- |
| Windows | 双击 `start.cmd`，或 PowerShell 执行 `& .\start.ps1` |
| Linux | 在项目目录执行 `bash start.sh` |
| macOS | 在项目目录执行 `bash start.sh`，或双击 `start.command` |

打开 http://127.0.0.1:8189 。关闭启动窗口或按 Ctrl+C 停止应用。没有自启动、计划任务或常驻服务；ComfyUI 与此应用可以独立启动、停止。macOS 如提示脚本不可执行，先在项目目录执行 `chmod +x start.sh start.command`。

启动脚本会创建 `data/runtime/venv`，首次启动时安装 `backend/requirements.txt` 所列依赖。需要 Python 3.10+，可通过 `PICTIDE_PYTHON` 指定解释器（旧 `PICTIDE_WEB_PYTHON` 仍可读取）；Linux 默认查找 `python3`，macOS 不提供合适 Python 时需自行安装。Windows 也会尝试使用 Codex 已有的 Python 运行时。Debian / Ubuntu 缺少 venv 时需安装与 Python 版本匹配的 `python3-venv` 包。不同操作系统分别创建运行环境，不直接复用 Windows 的 venv。

前端构建后由同一应用提供静态资源；日常启动不需要 Node.js 或前端构建服务，新检出目录需先按[开发流程](../development.md#首次准备检出目录)构建一次。脚本不会下载生图模型、词库或推荐模型。

自定义端口和数据目录：

```powershell
# Windows
& '.\start.ps1' -Port 8191 -DataDir 'E:\PictideData'
```

```bash
# Linux / macOS
bash start.sh --port 8191 --data-dir "$HOME/PictideData"
# 可选：指定 Python
PICTIDE_PYTHON=/path/to/python3 bash start.sh
```

`bash start.sh --help` 查看参数，`--lan` 开放局域网访问，详见[局域网指南](access.md)。相对数据路径按运行命令时所在目录解析，默认数据目录始终在项目内。

## 接入 ComfyUI

1. 启动 ComfyUI，打开 Pictide「设置 → 后端」，填写后端名称和实际地址，例如 `http://127.0.0.1:8188`。Desktop 的实际端口可能不同。
2. 保持“默认文生图”，读取并选择已安装的 checkpoint；留空自动使用列表中第一个模型，无需导入工作流或绑定输入。
3. 测试连接并保存，在「生成」页填写提示词并提交；「漫游」页专注浏览、评价与方向键操作。

内置工作流使用 ComfyUI 自带节点，适用于兼容 SD/SDXL 的完整 checkpoint，默认 1024×1024、28 步、CFG 5.5、DPM++ 2M / Karras、denoise 1。不会下载模型；Flux 等其他模型架构请使用对应的自定义工作流。

### 自定义工作流

需要自定义流程时，切换“自定义 API 工作流”，导入 **API 格式** JSON，选择正负文本、可选种子和图片输出节点。普通包含 `nodes` 数组的界面工作流不适用。清空自定义工作流会回退默认文生图；已有非空工作流保留为自定义。

设置中的「工作流」将名称输入与下拉选择合并：可选默认文生图、已保存工作流或自定义 API 工作流，也可直接输入名称并筛选已有项。选择已有项后修改输入文字就是重命名，保留原 ID；选择自定义项会填写可修改的默认名称，并避免与已有名称重复。点击「保存后端」同时保存模板到 `data/workflows` 并应用到后端，无需单独另存或应用。保存时核对读取的修订号，外部修改冲突会保留草稿并阻止覆盖。新建自定义工作流时，同名同内容复用已有模板，同名不同内容拒绝保存。模板更新前的版本保存在 `data/workflows/.backups`。

工作流更新应用于本次保存的后端，其他后端保留各自已保存的工作流快照；重新选择工作流并保存可应用最新版。已有任务始终使用提交时的后端配置，不受后续编辑影响。

删除工作流会从选择列表移除并保留文件备份，同时解除当前后端对模板的引用；后端中已经应用的节点、绑定和输出快照保留，可以继续生成。删除后端只移除当前可选配置，原配置修订、历史任务、图片和评价保留；已提交任务继续使用原配置执行。删除操作不会清理图片或 ComfyUI 数据，恢复说明见 [数据目录](../data-layout.md)。

默认文生图的「节点参数」可展开为自定义草稿，支持模型、尺寸、批次数、采样步数、CFG、采样器、调度器和降噪等普通输入；连线保持不变。API 工作流 JSON 默认折叠，展开后可编辑或导入 API JSON，普通参数编辑与 JSON 使用同一草稿。

### 提示词与图片记录

导入前请将工作流中的随机提示词生成节点替换为固定文本输入。平台把最终文本注入绑定的输入，工作流应将这些文本直接送入文本编码器，并保持输出提示词记录使用同一文本来源。不要在下游再次随机或改写文本，否则记录无法准确代表编码器实际输入。

ComfyUI 只执行生图 API，不再安装提示词生成、预览或提示词保存节点。工作流使用原生 PreviewImage / SaveImage 等图像输出，图片及对应的正负提示词 JSON 由 Pictide 保存。旧工作流如含已移除的 RulePrompt 节点，需要替换为原生文本输入和图像输出后再导入。

### 任务执行与检查

多个后端可分别保存。修改某个后端的地址或工作流后，旧任务继续使用提交时的后端配置，防止任务和图片指向错误的服务。新任务先订阅 ComfyUI 结束事件，再提交生图；全应用最多两个任务在途，通常一个出图、一个在 ComfyUI 排队；收到通知后通过 HTTP 核实，先补入下一项，再保存图片。通知不可用时自动回到轮询，详见 [任务事件通知](../issues/task-events.md) 和 [提交窗口](../issues/task-window.md)。生成完成后，Feed 将图片复制到 `data/images`，并保存同名 JSON，仅包含实际提交的正负提示词；不保存配置或额外 TXT。已保存图片可以在 ComfyUI 关闭后浏览。升级前的历史图片首次访问时补存，需要对应后端图片仍可读取。ComfyUI 自己的 output/temp 文件仍由 ComfyUI 管理。

测试连接执行只读预检，能发现常见的缺模型、缺输入图、连接或枚举错误；不提交生图，也不替代 ComfyUI 自定义节点的正式校验。HTTP 400 会展示可识别的节点及输入原因。

## 从源码开始

新检出仓库没有依赖、词库、推荐模型或前端构建产物。先按[开发流程](../development.md#首次准备检出目录)安装和构建；词库导入见[提示词指南](prompts.md#数据准备)，推荐模型准备见[推荐模块](../architecture/recommendation.md#模型准备)。数据路径和备份见[数据目录](../data-layout.md)。
