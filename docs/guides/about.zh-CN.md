# 认识 Pictide

[English](about.md)

[用户文档](../README.zh-CN.md#用户文档) · [开始使用](getting-started.zh-CN.md)

**随你漫游，画面世界徐徐展开。**

新的画面沿途生成，由你的反馈与锚点引导方向。

Pictide 是一款在本地运行、通过反馈逐渐贴近个人喜好的生成式图片漫游应用。浏览、表达喜好，随时引导下一张图片的方向。

## 满足什么需求

“我想看一些喜欢的画面，但不一定知道该怎么描述。”

完成初始配置后，用户无需先有明确的创作目标或精心编写的提示词，就能开始漫游。通过喜欢、不喜欢和锚点，在浏览中发现偏好、寻找视觉灵感，并逐渐引导后续画面的方向。有明确想法时，也可以输入提示词主动生成。

核心体验是一段持续发现画面的过程，既保留意外和新鲜感，也能引导接下来的方向。用户应当能在尚未理解 PMI、提示词种子和采样参数时开始探索，需要时再展开这些控制。

## 发现、引导、收藏

| 体验 | Pictide 如何支持 |
| --- | --- |
| 发现 | 共现生成提供画面组合，推荐系统结合个人偏好挑选候选，让浏览持续带来新的画面。 |
| 引导 | 用喜欢和不喜欢表达偏好，用锚点保留画面元素，用漂流、顺流、停泊控制变化。 |
| 收藏 | 留下偶然遇到的好画面，通过标签筛选和偏好评分排序浏览喜欢的图片。 |

## 漫游是体验核心

漫游连接生成、浏览和反馈，让用户把注意力放在画面上。生成、提示词和设置提供对这段体验的控制：

| 栏目 | 在产品中的作用 |
| --- | --- |
| 漫游 | 发现画面、表达偏好并调整探索方向。 |
| 生成 | 按明确想法或预设主动生成图片。 |
| 喜欢 | 保存和整理值得留下的画面。 |
| 提示词 | 管理固定词与共现预设，预览可能的画面组合。 |
| 设置 | 配置生图后端、漫游方式和数据管理。 |

## 本地与个人

图片、词库和偏好保存在本地，用户掌握自己的生成资源与数据。ComfyUI、OpenAI Images 或 Gemini 提供生图能力，Pictide 组织候选、推荐和浏览体验。使用云端后端时，提示词和生成参数会发送给所选服务；本地保存数据并不表示云端生成可以离线运行。当前同一实例共用图库和偏好；局域网访问仍使用这套数据，没有多用户账号隔离。

## 产品边界

Pictide 围绕漫游中的发现、引导和收藏安排功能，以下边界用于确定优先级：

| 相邻产品类别 | Pictide 的范围 |
| --- | --- |
| ComfyUI 替代品或完整前端 | 连接 ComfyUI，接入 API 工作流，提供探索所需的控制；节点图编辑、自定义节点管理和推理优化由生图后端承担。 |
| 提示词工程工作台 | 词库、预设和提示词控制服务于漫游；用户能使用准备好的默认值开始探索，需要更多方向控制时再展开。 |
| 模型安装器或模型管理平台 | 后端准备与可用的初始模型用于降低首次使用门槛；模型市场和通用环境管理属于核心体验之外的工作。 |
| 专业生产工作台 | 手动生成支持明确想法或预设；复杂图像编辑、合成和生产流水线属于当前产品重点之外的能力。 |

这些边界说明产品优先级，不代表新增功能承诺，也不改变现有启动准备要求。

## 当前机制与学习边界

Danbooru 标签共现是当前组织候选提示词的方法。推荐根据生成图片关联的反馈，对完整提示词组合评分；学习的是提示词与偏好的关联，尚未直接分析图片的视觉特征，也不代表完整理解了一个人的审美。

喜欢和不喜欢提供明确反馈，未评价保持未知，撤回反馈取消该评价。学习在后台进行，保存评价不代表下一张图片会立即变化或符合个人喜好。锚点和漫游方式提供另一条主动控制方向与变化程度的路径。

产品定位是图片漫游；当前词库、候选算法和生图模型是实现选择。未来的实现应保留表达偏好、引导探索的体验，具体机制调整仍需另行设计和验证。现有实现细节见[推荐架构](../dev/architecture/recommendation.zh-CN.md)。

## 体验目标

用户能轻松遇到喜欢的画面，同时持续获得新鲜感。优先关注：

- 从初始配置到第一张图片的路径清晰，默认值易于理解。
- 等待尽可能短且可预期，生成、等待和失败状态清晰。
- 反馈和锚点可靠，控制项让探索方向与变化程度容易理解。
- 在熟悉元素与新可能之间保持平衡，并始终保留主动引导的空间。
- 喜欢的图片容易收藏，也容易重新找到。

判断新功能时，先问：**它能否让用户更轻松地遇见喜欢的画面，或更自然地控制接下来的探索？** 模型选择、候选算法、预取机制和界面控制都应围绕这些体验评估。这些是设计目标，不是对生成时间和画质的保证。
